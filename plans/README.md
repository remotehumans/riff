## Findings considered and rejected / deferred

- **`cli.py` single `recv(8192)` can truncate large responses** (`riff-voice/src/riff/cli.py:15`):
  real but only `list_devices`/`list_voices` approach the limit and the CLI isn't used for
  those by the UI. Not worth a plan; fix opportunistically if cli.py is touched.
- **Interrupt button gated on up-to-2s-stale `speaking` state** (`PopoverView.swift:127`):
  cosmetic; enabling the button always was considered and skipped — `interrupt` is
  harmless when idle. Revisit only if users report it.
- **`riff-bridge` spawns a python3 process per ring-escape interrupt**
  (`riff_bridge.swift:272-296`): works, ~100ms overhead on a manual gesture; a native
  Swift socket write is nicer but low value. Deferred.
- **`/tmp/riff.sock` predictable path**: acceptable on a single-user Mac; socket is
  chmod 660 and stale files are unlinked at start. No action.
- **`config.py` dead fallback `merged.get("audio_mode", "duck")` defaulting differently
  from DEFAULTS ("pause")**: dead code — DEFAULTS always supplies the key. Harmless;
  tidy opportunistically.
- **No CI / no automated test baseline**: plan 002 seeds `tests/` with the first pytest
  suite; a CI workflow is deferred until the repo is public/shared enough to warrant it.
- **AUDIT.md thread-safety finding (#2, RingBridge state)**: by-design single-thread
  contract, documented in `riff_bridge.swift:15-17`. Not re-planned.
- **Daemon RSS/model footprint**: the Kokoro model is the product ("local, no cloud");
  resident memory is the accepted trade. The observed 1.1GB problem was RiffBar (plan 001),
  not the daemon (12MB RSS at audit time).
